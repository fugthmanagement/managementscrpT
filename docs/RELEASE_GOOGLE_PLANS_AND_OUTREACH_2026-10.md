# FUGTH release checklist — October 2026

This release changes public/login/workspace art direction, adds safe per-business Google connection onboarding, and restricts paid CRM/phone/booking features. It also adds founder-only call approaches, spreadsheet outreach and contact editing.

## Before considering payment/Google features production-verified

1. **Google Cloud Console**: in the project associated with FUGTH's OAuth client enable **Google Calendar API** and **Google Drive API** (enable Sheets API too if founder prospect sheets are used; Docs API for owner notes). Configure a verified OAuth consent-screen domain and app name, privacy policy, contact email and requested scopes. Under Testing, add testers; Testing refresh tokens can expire after seven days. Commercial launch using sensitive scopes may require Google's verification.
2. **OAuth Web client**: verify the Authorized Redirect URI is exactly `https://www.fugthmanagement.space/api/integrations/google/callback`; authorize `fugthmanagement.space` and `www.fugthmanagement.space` origins if used. Do not use an unregistered Vercel preview URL.
3. **Vercel production environment**: confirm `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `INTEGRATION_ENCRYPTION_KEY` (64 hexadecimal characters representing 32 bytes; **do not rotate without migrating encrypted tokens**), `NEXT_PUBLIC_APP_URL=https://www.fugthmanagement.space`, and Firebase Admin credentials (`FIREBASE_SERVICE_ACCOUNT` OR `FIREBASE_CLIENT_EMAIL`+`FIREBASE_PRIVATE_KEY`). Do not paste secrets in issues, chat or source code. Re-deploy if settings changed. The connected Vercel tooling previously returned 403 for this team's environment scope, so this requires someone with Vercel permissions.
4. **Test with two separate business accounts**: each account signs in, explicitly connects Google in Settings → Connections, chooses **Check Google connection**, and sees Calendar and Drive API checks pass. Book an example appointment, check it appears on only that business's dedicated Google Calendar, modify/cancel it and press **Sync appointments now**. Confirm no calendar events leak to another business.
5. **Test Drive with non-sensitive data**: upload an image as one business, confirm it is stored in that business's Google Drive when connected; verify a completed voice call's recording is archived and playable through the authenticated FUGTH proxy. Unconnected businesses may use the founder-managed fallback archive if configured. Never make Drive files public to work around a permissions error.
6. **Firebase Firestore security rules**: the repository includes revised `firestore.rules` for entitlement checks on calls, customers, appointments, marketing, and direct client writes to phone setup/booking hours. **Vercel deployment does not deploy Firestore rules.** First review the diff and test it in a Firebase rules emulator/staging project, then as an authorized project administrator:
   `npx firebase-tools@latest deploy --only firestore:rules --project YOUR_FIREBASE_PROJECT_ID`
   The `firebase.json` in the repo points to `firestore.rules`. Do not claim strict CRM data isolation by plan until Firestore rules are actually live and tested; server-side protected endpoints already check entitlements.
7. **Plan tests**: Zero and website-only should see Calls/Customers/Phone/Booking previews locked, with Website Maker accessible according to website entitlement; Essential should unlock voice, CRM and booking; Growth adds email tools; Elite adds automation. Verify feature buttons **and raw API requests**, then direct Firestore SDK access after deploying rules. Founder preview tiers affect UI only; actual account billing is server-authoritative.
8. **Sales outreach**: admin Sales → Pierre's Call Map now includes original approach plus four optional scripts. Sales → Email & Phone Outreach imports CSV exported from Excel/Sheets, keeps consent OFF by default, preserves DNC flags, stores personal preview URLs and supports one-at-a-time drafts. It does **not** auto-send unsolicited campaigns. Review contact law, calling hours, consent, suppression list and commercial email footer including your genuine mailing address before sending.
9. **Visual**: check `/`, `/login`, `/dashboard` on desktop and mobile, and verify FUGTH custom Signal artwork, editorial headline, navigation and interactive controls. A Vercel READY build is compilation confirmation, not authenticated visual or end-to-end verification.

## Current scope / limitations

- Google login is separate from Calendar/Drive consent. FUGTH offers a connection prompt after account sign-in (Google or email), but cannot grant scopes without the owner's explicit authorization.
- Calendar import happens while the signed-in workspace is open or on explicit sync; it is **not** continuous 24/7 background polling. Real bookings perform provider availability checks before creating an event.
- Voice recordings save to the business's own Drive when separately connected. Older archive entries preserve the Drive owner originally used.
- Website-only plans can edit **public opening hours**; these are not the same as paid appointment-booking restrictions.
- XLSX workbooks should be exported as CSV before founder Sales outreach import. No automated bulk phone outreach is enabled.
- No live OAuth, email provider delivery, card charge or Firestore rules deployment can be certified solely from GitHub commits or successful Vercel builds.
